# Region Component Labeling

This document defines the reviewed-label contract for region/component selector
training. It applies to CSVs generated by:

```text
scripts/analysis/build_region_component_review_pack.py
```

The generated `component-labels-template.csv` can be filled manually or by an
AI visual-review pass, then passed to:

```text
scripts/analysis/train_region_component_ranker.py --label-csv <labels.csv>
```

## Label Values

Use one of these values in the `label` column:

| Label | Meaning | Ranker treatment |
| --- | --- | --- |
| `keep` | Candidate edit visibly improves this component and does not damage printed/background content. | positive |
| `drop` | Candidate edit visibly worsens this component, damages print/background, or creates distracting artifacts. | negative |
| `review` | Ambiguous; not safe enough to use as a training positive or negative yet. | ignored by default |

The ranker also accepts equivalent values:

```text
positive: accept, keep, safe, positive, 1, yes
negative: reject, drop, unsafe, negative, 0, no
```

Prefer `keep` / `drop` / `review` in new reviewed-label files so the file
communicates the decision clearly.

## Visual Criteria

Label a component `keep` only when all are true:

- The candidate removes or reduces handwriting, residual ink, or visible dirt.
- Printed text, ruled lines, diagrams, and paper texture are not visibly damaged.
- The local background tone remains natural relative to surrounding paper.
- The improvement is visible at crop scale, not just a metric artifact.

Label a component `drop` when any are true:

- Candidate removes or lightens printed content.
- Candidate creates a white patch, halo, gray smudge, or paper-texture mismatch.
- Candidate changes background where the baseline was already acceptable.
- Candidate makes handwriting/residual ink more visible or visually distracting.

Use `review` when:

- The crop is too small, blurry, or context-poor to decide.
- The target panel looks suspicious or does not represent a realistic product target.
- The candidate helps one mark but harms nearby print/background.

## Required CSV Columns

The label CSV must include at least:

```text
split,file,component_id,label
```

The review-pack template includes extra audit columns such as `bucket`,
`component_gain`, `component_verdict`, `crop_review_image`, `flags`, `reviewer`,
`review_date`, and `comment`. Keep these columns when possible; they are useful
for debugging selector failures, but only `split`, `file`, `component_id`, and
`label` are required for training.

## Training Notes

`train_region_component_ranker.py` uses reviewed labels only for matching
components in the training splits. Unlabeled or `review` components are ignored
for training when `--label-csv` is supplied.

Held-out scoring still reports weak local-proxy verdicts unless a held-out label
CSV is also supplied. Treat reviewed-label training as selector evidence only
after verifying on separate reviewed held-out labels.

Recommended first pass:

```text
1. Generate a balanced review pack with 20-40 keep, review, and drop examples.
2. Fill `label`, `reviewer`, `review_date`, and short `comment` for edge cases.
3. Train with `--label-csv`.
4. Generate predictions and inspect top selected held-out components visually.
5. Promote only if held-out reviewed reject rate is near zero at useful coverage.
```
